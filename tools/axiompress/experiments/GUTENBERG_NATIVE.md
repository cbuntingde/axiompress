# Gutenberg / native API integration experiment

This operator-only experiment is served exclusively by the disposable database harness with `--editor-proof`. It does not add a route or assets to the native production router and does not replace either administration implementation. It uses real `BlockEditorProvider`, `BlockList`, `WritingFlow`, `ObserveTyping`, `RichText`, `BlockInspector`, `InspectorControls` and keyboard/format controls from the pinned local Gutenberg build. The block outline uses the `__experimentalListView` alias because the pinned build does not export a stable `ListView`; the inventory pins the exact scripts, so an upgrade that removes the alias fails explicitly instead of silently. A reviewed three-block inserter menu (paragraph, heading, published image) and a native Document/Block sidebar are mounted inside the provider; the Document panel drives publication, taxonomy and schedule reads through native endpoints. Core-owned paragraph/heading/image registrations are intentionally small; the full block library, edit-post frame, server-side render and core-data layers are not loaded.

## Repeatable execution

On the Windows development host, installed Chrome, Node, repository Playwright dependencies and the dedicated AxiomPress-Linux WSL Docker daemon are prerequisites. Run:

The pinned Gutenberg build and WordPress vendor assets must already have been generated by the repository's development setup; they are ignored build artifacts, not files supplied by Composer. Missing files fail the inventory explicitly. This proof does not fetch a newer artifact or silently substitute npm packages.

```
wsl -d AxiomPress-Linux -u root --exec python3 /mnt/c/chris-dev/wordpress-develop/tools/axiompress/database/run-checks.py --editor-proof
```

The harness creates disposable credentials/data, authenticates through the real session API, serves exact allowlisted local assets, verifies their hashes during the run, and removes the fixture. Passwords enter the Windows browser test over stdin, never command arguments. Certificate trust is limited to a fresh test browser context; system trust and the normal Chrome profile are unchanged. This platform-specific proof is not a portable production editor deployment.

Generate the dependency inventory with `node tools/axiompress/experiments/gutenberg-native.cjs`. Its output records script source paths, bytes, dependencies and SHA-256 values. Dynamic worker imports are recorded but not served; unexpected static module dependencies fail inventory generation. The graph explicitly excludes the full editor, core-data, plugin registry, server-side-render and block-library bundles. `api-fetch` is present as a transitive preferences utility: a deny-all handler is installed before mounting the editor. Native session/content operations use a separate bounded same-origin fetch adapter. The browser trace checks external requests and WordPress route use; absence of requests in this workload does not prove every optional component has been decoupled.

The proof loads 43 scripts totaling 5,374,354 bytes using the pinned build's production-minified files. The first unminified inventory totaled 12,893,348 bytes. Minification alone does not make this an acceptable production performance budget. A reviewed minimal source build, production CSP integration, tree-shaking and measurements are follow-up gates. No package version was upgraded for this experiment.

## Authority and failure behavior

The editor gets current identity/CSRF from `/v1/session`; it never supplies actor/site authority in JSON fields. Drafts use `/v1/articles` POST/PUT with expected native revision/version and a stable idempotency key. Publication is a separate explicit command. While a write outcome is unknown, editing and competing actions are frozen and retry retains the original intent/key. Confirmation clears the intent before follow-up reads, so a failed read cannot duplicate a successful create. Stale edits and expired sessions retain the in-memory buffer. Refreshing a session requires the same account and site. Closing the tab still loses unsaved edits; autosave/recovery is not implemented by this experiment.

Only the native versioned bold/italic paragraph/heading subset is editable. Published images can be embedded through a picker limited to ready, public site images; the proof has no upload path and uploads happen through the native workspace or API first. No arbitrary HTML block, plugin script, embed, remote media, core-data compatibility server or privileged PHP callback is enabled. Initialization mounts an inert editor shell; unknown document types/attributes are rejected before their content is mounted and before editing is enabled. They do not trigger an automatic save. See `src/axiompress/Blocks/README.md` for the authoritative document/render contract.

The fixture CSP admits same-origin scripts without unsafe script execution and allows inline **styles** required by the reviewed Gutenberg components. This explicit development concession is not a production CSP decision. Worker creation is denied by default-src; upload/codec worker assets are not in the asset map. Any real upload adapter must use the isolated media service, not enable browser/core decoding as a shortcut.

## Provenance and maintenance

Gutenberg artifacts come from the existing `package.json` pin `cc75a79186fd23e72eb015d594e82f40c6209eb5`, GPL-2.0-or-later, The WordPress Contributors. The experiment serves them unchanged from the local build; their original source notices are retained. React/ReactDOM/JSX-runtime and Moment come from the existing WordPress vendor build, with exact local hashes in the inventory and their existing notices/licenses retained in the repository/dependency distribution. This does not establish an independent upstream provenance audit for every transitive vendor artifact. Verify and package all corresponding licenses/source provenance before any production bundling. There is no copied upstream PHP runtime code in the experiment.

The new format registration, document adapter, asset inventory and fixture/browser orchestration are AxiomPress integration code. The existing native authentication, authorization, optimistic commands, outbox and reader roles remain authoritative. A future commit/PR must reference the pinned Gutenberg revision, selective component adaptation and actual verification results. Preserve the fork baseline and use selective upstream review rather than routine synchronization.

## Acceptance boundary

Actual browser tests cover rich-text editing/formatting, native save/reload, explicit publication and unpublication, undo/redo, synthetic plain-text paste through the real contenteditable handler, lost-response retry, stale edits, session denial/renewal, network routing, viewport overflow, published-image selection with a native save/reload round-trip, the three-block inserter menu, the Document/Block sidebar with heading-level control and taxonomy apply, and the collapsible list view. This is not an operating-system clipboard or rich-HTML paste test. PHP tests independently reject unsafe markup and preserve older serialization. A passing test is a development component proof, not full Gutenberg/admin parity, independent security audit, image upload acceptance, accessibility certification or Phase 4 completion. Broader populated-media browser acceptance is exercised separately with `--browser --isolated-media`; magic-only SQL image fixtures are removed before those real decoder/browser cases.
