# Gutenberg grammar and parser attribution

The native administration asset `public/assets/block-parser.js` contains the reviewed, dependency-free Gutenberg `@wordpress/block-serialization-default-parser` build. Source: WordPress/gutenberg commit `cc75a79186fd23e72eb015d594e82f40c6209eb5`, package version 6.0.0, GPL-2.0-or-later, The WordPress Contributors. The package metadata and license were checked from the exact GitHub revision; the compiled artifact was already pinned by this repository's Gutenberg build configuration.

Original artifact: `gutenberg/build/scripts/block-serialization-default-parser/index.js`, SHA-256 `971d407801aeecf44b9ff0f435ca5f1e7e8f378fc9a576d62dc7e511f4680a88`. Adaptations: add attribution header and remove its unavailable source-map URL. Runtime code is unchanged. The pinned GPL license is distributed beside it as `public/assets/LICENSE.txt`. The original fork baseline in FORK_PROVENANCE.md remains unchanged.

The first-party JavaScript parser preserves block comments/attributes/HTML as data. It is not validation or sanitization. The independently implemented PHP Document class accepts only a canonical bounded Gutenberg-grammar subset: core/paragraph, core/heading (levels 2–4) and axiom/image with an opaque native media ID and alternative text. Existing plain text remains plain text. Unknown blocks and arbitrary markup inside supported blocks are rejected explicitly. No block callback registry, plugin/theme PHP, HTML block, script or imported package executes.

The textarea administration adapter reads parser output as data and creates form controls with text/value APIs. The separate disposable Gutenberg component proof uses an explicit versioned rich-text subset and native API adapters, described in README.md and tools/axiompress/experiments/GUTENBERG_NATIVE.md. Server validation and fixed contextual output encoding remain authoritative. The Phase 5 importer must report unsupported blocks and transformations rather than treating parser acceptance as safe rendering.
