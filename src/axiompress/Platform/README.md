# Native workspace data

The independent workspace is `/admin`. It uses core-owned static assets, secure HttpOnly session cookies and an in-memory CSRF token. No plugin scripts, remote assets, inline scripts, raw HTML editor or PHP theme callbacks run in its origin. The writing canvas supports canonical paragraph, heading and native image blocks; see `../Blocks/NOTICE.md` for the reviewed Gutenberg parser provenance and the distinction between parsing and validation.

The article editor explicitly saves drafts, publishes a saved revision, unpublishes, schedules and cancels publication, and restores history as a **new draft revision**. Optimistic revision/version checks reject stale updates. Uncertain writes retain their original payload and idempotency key until resolved. Drafts are not saved to browser storage. Keep the tab open to retain unsaved text across sign-in renewal; closing or discarding it loses unsaved text. A prepared private image must be explicitly published before an article can publish it.

`POST /v1/platform/<operation>` exposes only the fixed fields in `Kernel::FIELDS`, with current-session checks, exact Origin and CSRF even on private queries. Actors and sites never come from request fields. List queries are bounded: 25 articles with a descending ID cursor, 100 media items (the site quota), 100 recent revisions, and 256 taxonomy terms. Authors see their own work; editors and owners see site work. The database reauthorizes each command atomically through function-only grants.

Site title, tagline, paper/ink theme and page size are typed settings; only owners can change them. Categories/tags have typed names, slugs, kinds and compare-and-swap versions. Editors/owners create or archive terms. Relationships are immutable revision snapshots. Editing/archiving a global term never changes the published snapshot; applying relationships creates a draft revision. At most 16 terms belong to a revision. Restoring history copies the original term and image snapshots. Applying categories is a separate draft action and requires saved article text.

Public `/site/{site}` and `/site/{site}/articles/{id}` use declarative core templates and the restricted PostgreSQL reader. Titles, terms and text are contextually escaped. Images use only core media URLs. Themes can choose a fixed palette, not executable code or arbitrary CSS. `/preview/{id}` requires current private article authority and uses authenticated media reads; it is never a public sharing link. All these responses are no-store. Optional plugin invocation retains the public kernel's current-publication recheck.

The database fixture's `--browser` option runs installed Windows Chrome against a temporary HTTPS site on AxiomPress-Linux. It verifies saves, publication versus new private revisions, escaped preview/public HTML, settings, lost-response retry, session renewal, logout and desktop/mobile overflow. Test screenshots remain in ignored `docs/phase4-admin/`.

Migration mapping: WordPress posts/revisions, terms and relationships require an offline, versioned mapping into native site/article/revision IDs. Import supported block data through canonical validation; report unknown blocks and formatting loss. Convert only explicitly supported options to typed settings. Do not deserialize arbitrary options or preserve executable themes/plugins. Import support remains Phase 5 work.
