# Architecture experiments

Operator-only evidence for Phase 1 decisions. These tools use controlled fixtures, not production data or untrusted publisher uploads. They do not install/reconfigure a Docker runtime or migrate the development CMS. Run supervisor stress, live, admission, benchmark and loaded harnesses sequentially: they share an exclusive prototype namespace. The loaded runner asserts that namespace is initially idle; it is not a multi-host production admission service.

- database.py starts a disposable networkless PostgreSQL 18 container pinned by digest, verifies 18 role/authentication/tenant/transaction/revision/restore invariants, and removes the entire experimental container/tmpfs. SCRAM protects TCP reader connections; operator-only local access uses peer authentication. TCP readiness excludes the transient initialization server. It does not contact the existing MySQL database. Need the specified official image locally (docker pull postgres:18 then confirm its expected digest) or permit Docker's digest pull.
- editor.cjs reads the pinned Gutenberg artifact already built in gutenberg/build/scripts. It exercises grammar/data parsing and records actual dependency manifests/hashes. Run node tools/axiompress/experiments/editor.cjs. Node vm is only a compatibility harness for trusted pinned code; it is not an extension sandbox or HTML sanitizer.
- The later native Gutenberg component proof is documented in [GUTENBERG_NATIVE.md](GUTENBERG_NATIVE.md). The disposable database harness's `--editor-proof` option runs real BlockEditorProvider/BlockList/RichText against native HTTPS/PostgreSQL commands, without replacing the administration UI or mounting experiment routes in the native application.
- runtime.ps1 verifies a pinned official gVisor multi-file release archive, exports the local immutable hostile-fixture image and runs runtime-oci.py in a temporary trusted privileged toolbox with no network, Docker socket, repository or core credentials. It needs the local worker fixture image. No daemon runtime is registered. Rootfs tar extraction is limited to that trusted image export; do not point it at arbitrary archives. The nested ignore-cgroups profile proves compatibility/configured boundary behavior only and must never be deployed as the production isolation boundary.
- worker-profile.py uses the currently approved image from docs/axiompress-policy-runtime-last.jsonl. It replaces the entrypoint with the existing /usr/bin/time for controlled profiling, with the same non-root/read-only/network/resource restrictions. Sixteen profiles cover empty, five-word, Unicode and near-input-limit text. It measures complete PHP child lifetime peak RSS, not total cgroup/page-cache/runtime memory. Replies are synthetic, so use live broker tests for authority proof.
- load.py needs the rebuilt supervisor image, approved image record, SDK image and native development endpoint on port 8890. It runs four actual policy-backed isolated useful workers against distinct site/install fixtures, holds all shared slots, checks immediate rejection, and measures 16 concurrent public/private native HTTP responses. It then verifies worker cleanup. Fixture sites are not a claim of multisite product support. Rebuild supervisor after editing load-test.php.
- resource-probes.py measures actual near-cap PID saturation of a controlled fork shell inside the worker image and verifies whole-container removal. The PHP parent keeps the container alive when the shell hits fork refusal; observed child count may be 15 under a 16-task cgroup limit. A separate busy PHP loop samples CPU use under the inspected half-core quota; it is corroborating resource evidence, not a throughput claim. The supervisor hostile suite separately tests tmpfs fill, network destinations, OS OOM, output floods and deadlines.

Raw results live in ignored docs/. Set up design-schema validation using python -m pip install --target .cache/axiompress-schema-validation -r tools/axiompress/experiments/requirements.txt, set PYTHONPATH to that directory for the current process, and run tests/axiompress/schema-test.py and tests/axiompress/domain-contract-test.py. The latter requires an active RFC3339 checker so date validation cannot silently disappear.

The architecture decisions and ownership live in tracked ARCHITECTURE.md. Current runc profiles are development evidence. PostgreSQL schema rollout, native gVisor integration/resource enforcement, full editor UI, jobs/mutations, production audit/release/deployment and data migration retain later-phase acceptance gates.
