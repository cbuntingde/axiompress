# Native authentication

Core owns these routes; no inherited bootstrap, cookies, plugins or pluggable authentication are loaded. This slice implements login and session lifecycle, with private article commands documented in [Content](../Content/README.md). It does not implement an administration UI, signup, recovery or password provisioning endpoints.

| Route                    | Contract                                                                                                                                       |
| ------------------------ | ---------------------------------------------------------------------------------------------------------------------------------------------- |
| `POST /v1/session/login` | Exact JSON string fields `username` and `password`; canonical lowercase ASCII username; returns the current principal and sets a fresh cookie. |
| `GET /v1/session`        | Resolves the cookie against current database state and returns the principal and CSRF token.                                                   |
| `DELETE /v1/session`     | Requires the cookie, exact configured Origin and `X-CSRF-Token`; revokes the session and clears the cookie.                                    |

Principal identifiers are decimal strings, preserving 64-bit IDs in JavaScript. Responses contain role, absolute expiry and a session-bound HMAC CSRF token. They never return the session token or credential hash. Errors are generic; responses are JSON with no-store, nosniff and a restrictive CSP. Unexpected configuration/database failures return the native non-disclosing 503 diagnostic.

The `__Host-axiom_session` cookie contains 256 random bits and has Secure, HttpOnly, SameSite=Strict, Path=/ and no Domain. Only its SHA-256 digest is stored. Login rotates a supplied old session. Duplicate session cookies and duplicate/extra JSON fields are rejected. Mutations require the exact deployment-configured HTTPS Origin; no permissive CORS or proxy-header authority is supported. GET permits a missing Origin for same-origin browser fetches. CSRF tokens are derived from the secret session token and exposed only through the authenticated same-origin JSON response.

Every session resolution checks the site's current membership/role, account status and credential fingerprint. Password changes invalidate existing sessions; disabled accounts or memberships cannot resolve sessions while disabled. Disable/reenable is not permanent revocation: delete that principal's session rows through the deployment identity when permanent revocation is required. Sessions expire after eight hours or thirty idle minutes. Each user has at most five sessions and each site at most 1024. Site-scoped transaction locks serialize login rate-state/session creation. Per fifteen-minute window, account attempts are limited to five and peer attempts to thirty; successful login resets only the account budget. Rate state is bounded to at most 4096 rows per site and fails closed at capacity. Rate limits intentionally allow availability denial against an account; production admission/load policy remains required.

Credential provisioning must generate Argon2id with `memory_cost=65536`, `time_cost=4`, `threads=1`. Other profiles fail closed using a fixed dummy verification; unknown users also incur verification work. The session-creation function rechecks the exact verified credential hash and active membership under row locks. It does not trust an earlier password check after a concurrent credential change. The native content function resolves and authorizes the actor again under transaction locks; returning a role here alone does not confer resource authority.

## Provisioning and deployment

Run the administrator-only `tools/axiompress/database/auth-bootstrap.sql` before applying migration 0002, including on databases that already applied 0001. Reserve the cluster-wide group `axiom_authenticator`. Provision one restricted SQL LOGIN per site, grant that group with INHERIT TRUE, and bind its OID to exactly one site in deployment-owned `axiom_auth.sites`. Supply its password through a read-only mount; never grant owner/deployer membership. The runtime group has only schema usage and execution of the fixed authentication functions: no credential-table, session-table, binding-table, content-write or DDL access. Its functions intentionally confer trusted core authentication authority; a compromised core process can mint sessions within its site. This boundary does not contain core compromise.

Configure `AXIOM_AUTH_PG_HOST`, `AXIOM_AUTH_PG_PORT`, `AXIOM_AUTH_PG_DATABASE`, `AXIOM_AUTH_PG_USER`, `AXIOM_AUTH_SITE_ID`, `AXIOM_AUTH_PG_PASSWORD_FILE`, `AXIOM_AUTH_PG_CA_FILE` and `AXIOM_AUTH_ORIGIN`. Database TLS always uses verify-full. Passwords are 16â€“256 bytes without a trailing newline. CA/password files must be bounded regular files mounted read-only. Login-OID bindings must be maintained when rotating or retiring database identities. Store checks the configured binding at startup and on returned principals.

The request must arrive via HTTPS. For an operator-controlled TLS proxy and private backend only, `AXIOM_AUTH_TLS_TERMINATED=1` tells core that TLS already terminated. Exposing that backend directly defeats this transport assertion. Core ignores forwarded scheme, host and client-address headers. Rate limiting uses server `REMOTE_ADDR`; configure the trusted server layer to provide the verified client address or all users behind a proxy share its peer budget. Production FPM/proxy, admission, audit retention, credential enrollment/recovery and operational acceptance remain deployment work. The PHP built-in server is a development adapter.

Run `python3 tools/axiompress/database/run-checks.py` as root on the dedicated Linux Docker host. It tests real PostgreSQL permissions, lifecycle, revocation, cross-site rejection and throttling, then exercises the actual native image through a verified local HTTPS proxy. Disposable secrets and databases are removed; evidence is written only to ignored docs. These checks do not establish production readiness or OS containment of core code.
