# Native AxiomPress core

This is the first replacement of the inherited bootstrap and database execution path. It requires 64-bit PHP 8.5 and PDO MySQL. It is an anonymous read-only API, alongside the existing development site. It does not provide authentication, administration, writes, migrations, block/shortcode rendering or legacy REST compatibility.

Only fixed sources in bootstrap.php load. Configuration is validated environment data plus a mounted password file; no executable wp-config.php, WordPress bootstrap, Composer plugin, hook, theme, database/cache drop-in or extension PHP is loaded. The standalone image contains this core directory only. Third-party workers never run inside it.

GET or HEAD /v1/sites/{site}/content/{id} returns api=axiompress.core/0.1 plus allowlisted site_id, content_id, revision, title and text. IDs must be canonical positive decimals. Query parameters and extra paths are rejected. The configured site owns exactly one deployment-defined view. Request headers/cookies cannot select a principal, site mapping, table, view or database. There is no privileged authentication fallback: requests always have anonymous authority.

PublicContentRepository uses native parameter binding and a SELECT-only public projection. Both the projection and repository enforce published, non-password-protected post/page content with a publication time no later than now. Private/draft/pending/trashed/future/revision/attachment/missing content and other-site requests return not_found. Fresh queries and no-store responses prevent application cache reuse after visibility changes. Already delivered public content cannot be recalled; reads observe database state at statement execution.

Core returns plain text with markup removed, not rendered HTML. Block comments and shortcode syntax confer no executable behavior. JSON escapes HTML-sensitive characters; responses use application/json, nosniff, no-store and a restrictive CSP. Clients must treat text as text rather than inserting it as HTML. Content bodies over 128 KiB and titles over 4 KiB are rejected before transfer from SQL; valid routes return 413 for these public records. Missing/unavailable configuration/database returns a non-disclosing 503 and diagnostic ID. Application diagnostics omit SQL, exception messages, credentials, URLs and content.

ComponentRenderer is the core-owned renderer for the separately validated reading_summary component. It accepts only its exact type and bounded integer word_count/reading_seconds, and emits one fixed span. It cannot accept plugin tags, attributes, URLs or HTML. The operator-only render-component.php adapter consumes already validated worker data on CLI stdin; it is not a web route. Unit injection/type/range cases and actual isolated-worker output are verified separately from the HTTP content endpoint.

Database ownership is separate from request execution. Deployment creates the public view and grants the application only SELECT on that view. It cannot read credential/options/base-post tables or mutate the projection. Read-only transaction mode is additional defense; it is not the credential boundary. The existing schema is a transitional read source, not the new CMS domain schema or a multisite compatibility promise.

Configuration: AXIOM_DB_HOST, AXIOM_DB_PORT, AXIOM_DB_NAME, AXIOM_DB_USER, AXIOM_DB_PASSWORD_FILE, AXIOM_PUBLIC_VIEW and AXIOM_SITE_ID. Only MySQL host/port/database data are accepted; caller-supplied DSNs and arbitrary identifiers are unsupported. Password files are bounded, regular files supplied read-only to UID 10001. Native credentials, policy storage, signing keys and worker runtime authority must remain separate.

Run tools/axiompress/native/run-checks.ps1 for the disposable local wordpress_develop database with wp_posts/site 1. It builds a fixed-source image, provisions a new read-only view/identity once, runs unit/database/HTTP checks and retains http://127.0.0.1:8890/v1/sites/1/content/9. Secrets/configuration stay under ignored .cache/axiompress-native. The operator setup is Linux-only and must run as an identity allowed to create the view/user and assign the password to UID 10001. It does not read WordPress configuration or execute extensions. Existing configuration is never overwritten; SQL grants and the secret file must be revoked/rotated together by the operator if this local fixture is retired.

The retained service has a non-root user, read-only root and password mount, dropped capabilities, no-new-privileges and resource limits. It has no repository mount or Docker socket. It joins the local database network and binds HTTP to host loopback. The PHP built-in HTTP server is a development adapter; it is not a production web server, concurrency model or supported deployment artifact. Automatic TLS, database TLS, production HTTP/FPM, request admission and operational recovery remain deployment work. No native code write path exists yet.
